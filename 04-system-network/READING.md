# Lab 4 Pre-Reading — System and Network Inspection

Read this before starting **Lab 4 — System & Network Inspection**. The goal is to learn a small set of commands that answer specific diagnostic questions about a Linux system without changing its configuration.

The core mental model is:

```text
ps                  snapshot of processes
top                 live/interactive process view
free                memory usage
dmesg               kernel messages

/etc                system configuration
/var/log            logs
/boot               boot-related files
/proc               virtual process/kernel information
/dev                device files
/sys                virtual kernel/device information

ip addr show        interface addresses
ip route show       routing table/default route
ping -c N HOST      send a limited number of ICMP echo requests
host NAME           DNS lookup
ss                  socket information

/etc/hosts          local static hostname mappings
/etc/resolv.conf    resolver/DNS configuration
```

This lab is primarily **read-only inspection of Prometheus**. You are looking at the real system, not changing its network or process configuration.

---

## 1. `ps` versus `top`

Both commands show process information, but they answer the question differently.

### `ps`: a snapshot

```bash
ps
```

prints a process listing and exits.

Think:

> What processes are visible at this moment?

Typical output includes columns such as:

```text
PID TTY          TIME CMD
```

The exact set of processes depends on how `ps` is invoked and on your current session. For this lab, the important Linux Essentials distinction is simply that `ps` produces a **snapshot**.

### `top`: a live view

```bash
top
```

opens an interactive display that refreshes repeatedly.

Think:

> What is the system doing now, and how is process activity changing?

Press:

```text
q
```

to quit `top`.

The high-value distinction is:

```text
ps     snapshot and exit
top    live/interactive process view
```

Do not spend this lab memorizing advanced `ps` or `top` options.

---

## 2. `free`: memory, not storage

`free` reports system memory usage:

```bash
free
```

You will normally see rows such as:

```text
Mem:
Swap:
```

This is a useful place to separate two concepts that are easy to blur:

```text
free    memory/RAM
df      filesystem storage
```

You already know `df -h` for disk/filesystem space. In this lab, the deliberate target is remembering that **`free` is the corresponding core command for memory information**.

A practical form you may see is:

```bash
free -h
```

where `-h` requests human-readable units. The exam-relevant command to retain is `free`; the human-readable flag is secondary.

---

## 3. `dmesg`: kernel messages

```bash
dmesg
```

shows messages from the kernel's message buffer. These can include information about:

- hardware detected during boot
- storage devices
- network interfaces
- drivers
- kernel warnings/errors

Because the output can be long, a common inspection pattern is:

```bash
dmesg | head
```

Some Linux systems restrict unprivileged access to the kernel message buffer. If Prometheus returns a permission error, that does **not** mean your syntax is wrong. On a system where you have appropriate sudo access, a read-only inspection can be done with:

```bash
sudo dmesg | head
```

For Linux Essentials, retain the association:

```text
dmesg = kernel messages
```

## 4. High-value Linux system paths

You do not need to memorize every Linux directory. For this exam plan, these six are especially useful.

### `/etc` — configuration

```text
/etc
```

contains system-wide configuration files and directories. Examples include account databases and networking-related configuration.

Memory cue:

```text
/etc = configuration
```

### `/var/log` — logs

```text
/var/log
```

is the conventional location for many system and service logs.

Memory cue:

```text
/var/log = logs
```

### `/boot` — boot files

```text
/boot
```

contains files related to booting the system, such as kernel and bootloader-related files depending on the distribution.

Memory cue:

```text
/boot = boot
```

### `/proc` — process and kernel information

```text
/proc
```

is a **virtual filesystem**. Its files are generated by the kernel rather than being ordinary persistent files on disk.

It exposes process and kernel information. Numeric directories such as:

```text
/proc/1
/proc/1234
```

correspond to process IDs when those processes exist.

Memory cue:

```text
/proc = processes + kernel information
```

### `/dev` — device files

```text
/dev
```

contains special device files representing devices and other kernel interfaces.

Memory cue:

```text
/dev = devices
```

### `/sys` — kernel/device information

```text
/sys
```

is another virtual filesystem. It exposes structured information about devices, drivers, and other kernel objects.

A useful distinction:

```text
/proc   especially process/kernel runtime information
/sys    structured kernel/device information
/dev    device nodes used to interact with devices
```

## 5. Linux networking: do not reach for Windows `ipconfig`

On Windows you may use:

```text
ipconfig /all
```

On modern Linux, the command family to remember is **`ip`**.

For interface addresses:

```bash
ip addr show
```

A common shorthand is:

```bash
ip a
```

For the exam, retain the explicit form:

```text
ip addr show
```

The output is organized by interfaces. You may see names such as:

```text
lo
eth0
ens18
enp1s0
```

Interface naming varies by system.

Address lines commonly begin with:

```text
inet
```

for IPv4 and:

```text
inet6
```

for IPv6.

---

## 6. IPv4 and IPv6 recognition

### IPv4

IPv4 addresses use four decimal numbers separated by periods:

```text
192.168.1.25
10.0.0.5
127.0.0.1
```

`127.0.0.1` is the familiar IPv4 loopback address.

### IPv6

IPv6 addresses use hexadecimal groups separated by colons and can use abbreviation rules:

```text
2001:db8::25
fe80::1234:abcd
::1
```

`::1` is the IPv6 loopback address.

For this lab, recognition is more important than subnet-calculation detail:

```text
inet     IPv4
inet6    IPv6
```

---

## 7. Routing: `ip route show`

A machine can have an IP address and still need routing information to know where to send traffic.

Use:

```bash
ip route show
```

to inspect the routing table.

A typical default route may resemble:

```text
default via 192.168.1.1 dev eth0
```

Conceptually:

```text
default         use this route when no more-specific route matches
via ADDRESS     next-hop router/gateway
dev INTERFACE   interface used to reach it
```

The exam-level distinction to retain is:

```text
ip addr show     addresses/interfaces
ip route show    routes/default gateway
```

## 8. `ping`: reachability testing

Basic form:

```bash
ping HOST
```

On Linux, plain `ping` normally continues until you stop it. The useful limited form for this lab is:

```bash
ping -c 4 127.0.0.1
```

`-c` specifies a count, so the command exits after the requested number of echo requests.

Remember that a failed ping does not prove that a host is down. ICMP traffic can be filtered. The command is still useful as a basic connectivity/reachability test.

You already demonstrated this syntax earlier, so Lab 4 uses it only as light reinforcement.

## 9. DNS lookup with `host`

The Linux Essentials command to associate with a basic DNS lookup is:

```bash
host example.com
```

The command asks the configured resolver for information about the supplied name.

For this exam plan, the key association is:

```text
host = DNS lookup
```

Do not substitute `dig` as your memorized exam answer. `dig` is useful real-world tooling, but it is deliberately outside the required v1.6 track for this project.

Some minimal Debian installations may not have `host` installed. If Prometheus lacks it, do not treat that as a syntax failure. You can still practice exact recall, and you may try the command in **WebTerm Free Play** if that sandbox exposes `host`. Do not install extra software solely to satisfy this lab.

## 10. `ss`: sockets and network connections

Use:

```bash
ss
```

to inspect socket information.

A socket is an endpoint used for communication. Depending on state and invocation, output can describe local/remote addresses and connection state.

The important modern/legacy distinction is:

```text
ss         modern socket inspection
netstat    older/legacy tool
```

You previously answered `netstat` when asked for the modern command, so this lab deliberately puts `ss` next to the legacy name.

Do not spend required study time memorizing a large collection of `ss` flags.

## 11. `/etc/hosts` versus DNS resolver configuration

### `/etc/hosts`

```text
/etc/hosts
```

contains local static mappings between names and addresses.

A line might look like:

```text
127.0.0.1 localhost
```

This is local configuration; it is not a DNS server database.

### `/etc/resolv.conf`

```text
/etc/resolv.conf
```

contains resolver configuration used by the system when resolving names. You may see directives such as:

```text
nameserver
search
```

The file may be generated or managed by another service, but the exam-level mapping remains:

```text
/etc/hosts        local static hostname mappings
/etc/resolv.conf  DNS resolver configuration
```

## 12. Modern versus legacy networking commands

Linux has older networking tools that remain common in documentation and on older systems.

Retain these conceptual mappings:

```text
modern                 legacy
---------------------------------
ip addr show            ifconfig
ip route show           route
ss                      netstat
```

The legacy commands may not be installed on a modern Debian server. That is fine. Recognition is the goal; do not install `net-tools` just to make them appear.

The critical trap is:

```text
ipconfig    Windows
ifconfig    legacy Linux/Unix networking tool
ip          modern Linux networking tool
```

## 13. Read-only inspection mindset

Many useful Linux administration commands simply inspect current state.

This entire lab is built around:

```text
observe -> interpret -> record
```

rather than:

```text
change -> hope -> recover
```

Commands such as:

```text
ps
top
free
dmesg
ip addr show
ip route show
ss
host
cat /etc/hosts
cat /etc/resolv.conf
```

are inspection commands in the way this lab uses them.

This makes Prometheus a better learning target than a simulated filesystem for Lab 4: the addresses, routes, processes, memory, sockets, and resolver configuration are real.
